# WebSocket 分片压测报告（perf4）

## 1. 测试概述

- 测试时间：2026-08-16
- 目标地址：`ws://8.130.151.211/api/v1/ws`
- 监控端点：`http://8.130.151.211:6060/metrics`
- 压测工具：k6 v1.6.1 + Node.js 指标采集器
- 数据目录：`perf4/`
- 测试环境：2C8G云服务器
- 测试用户：`perf4/users.json`，共 2000 个现成 JWT
- 测试房间：500 人群 `room_id=4`，1000 人群 `room_id=5`
- 本次不压测 Agent，不在启用 Agent 的群聊中压测

## 2. 总体结论

- WebSocket 建连在 100/500 并发下成功率 100%。
- 1000 并发纯建连时服务端峰值在线 938/1000，达到 93.8%，比上一轮 `perf2` 的 912 有提升。
- 500 人群广播端到端 P95 从上一轮 243.3ms 降到 99ms。
- 1000 人群广播端到端 P95 从上一轮 180ms 降到 71ms，服务端峰值在线从 912 提升到 949。
- Hub 任务池在 500/1000 人群广播时仍会打满 256，但等待队列保持 0，说明分片后任务派发更平稳。

## 3. WebSocket 建连爬坡

| 目标 VU | K6 WS sessions | 服务端峰值在线 | 建连 P50  | 建连 P95  | 建连最大     |
| ----- | -------------- | ------- | ------- | ------- | -------- |
| 100   | 542 sessions   | 100     | 80.72ms | 88.12ms | 113.03ms |
| 500   | 500 sessions   | 500     | 80.33ms | 88.46ms | 105.99ms |
| 1000  | 982 sessions   | 938     | 80.64ms | 1.04s   | 21.06s   |

说明：

- 100 VU 和 500 VU 为“只建连、不短连接重连”的纯爬坡结果，成功率 100%。
- 1000 VU 建连 P50 仍约 80ms，但尾部出现 21s 超时重试；K6 session 计数为 982，服务端峰值在线 938，说明 1000 并发已接近单机容量边界。
- 上一轮 `perf2` 中 1000 人广播场景服务端峰值在线为 912，本轮纯建连峰值在线为 938，分片后连接注册路径有改善。

## 5. 服务端关键指标

| 场景         | WS 峰值在线 | Hub 任务池运行峰值 | Hub 等待峰值 | Kafka lag | DB in_use 峰值 |
| ---------- | ------- | ----------- | -------- | --------- | ------------ |
| WS 100 VU  | 100     | 0           | 0        | 0         | 0            |
| WS 500 VU  | 500     | 0           | 0        | 0         | 0            |
| WS 1000 VU | 938     | 0           | 0        | 0         | 4            |
| 广播 500     | 500     | 256         | 0        | 0         | 0            |
| 广播 1000    | 949     | 256         | 0        | 0         | 0            |

说明：

- 广播时 Hub 任务池运行数达到 256，但 `im_hub_task_pool_waiting` 一直为 0，说明分片后的单房间派发没有进一步排队堆积。
- Kafka consumer lag 全程为 0，生产到消费链路无积压。
- DB 连接池未耗尽，本轮读/写路径压力不高。

## 6. 主要风险

- 1000 VU 纯建连和 1000 人广播已接近当前单节点容量边界，连接尾部长尾仍存在。
- 500 VU 若采用 5 秒短连接并同步重连，会出现 12.10% 的握手失败；生产环境应避免大量客户端在同一时刻重连，或在上层加入抖动/退避。
- Hub 任务池容量仍为 256，500/1000 人广播时已打满；继续扩容需要提升任务池容量或按房间拆分发。
